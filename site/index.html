Prior authorization metrics for one clinic

Synthetic data for Lakeshore Specialty Clinic. This is not a Develop Health product.

Problem

Prior authorization sits between a prescription and the medicine. A clinic needs to see whether a case is waiting on a benefit check, a missing note, a payer decision, or an appeal. Approval rate, time to a decision, and a stuck case only help if they mean the same thing every time someone asks. A sentence that invents a number is not a metric.

Solution

Raw case events are messy. Some arrive late, some are duplicated, and a decision can be corrected. This demo loads that feed with dbt. Staging and intermediate models repair it into one case spine. Marts publish the metrics. The semantic layer is the allow list an agent may use. In Snowflake, each clinic would be fenced by a row access policy. The demo applies that same tenant filter in the clinic mart and in every clinic question. Tests check the grain, the clocks, and the bridge rules.

Where cases stall

Each bar is a count from the funnel mart. A later stage is a subset of the one before it. Cases also leave when a drug is covered with no prior authorization, when a plan exclusion is denied before submission, or when the case is abandoned. Those exits sit under the bars so the drop is not one stalled pile.

Cases past the stage SLA

A case is stuck when it is still open and has been in the current stage longer than the SLA. A case sitting exactly on the SLA is not stuck. The clock stops at November 2, 2026.

Approval rate and median hours to decision

Approval rate uses decided cases. Median hours use cases that have both a submission and a decision. Both numbers are the defined metrics, sliced by one dimension.
